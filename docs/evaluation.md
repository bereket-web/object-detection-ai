# Evaluation protocol

## Similarity-aware split and data integrity

The preparation step validates all 59 JPEGs and YOLO label files from the pinned source revision and records file SHA-256 digests. It computes a 63-bit grayscale DCT perceptual hash (32×32 resize, low-frequency 8×8 coefficients excluding DC) and joins images into transitive connected components when Hamming distance is at most 4. The observed visual-group sizes are 1, 20, 37, and 1 images.

The entire 20-image component is held out as the test group. The remaining 39 images are shuffled with seed 2026 into 30 training and 9 validation images. The similarity audit reports zero test-to-train/validation pairs within the pHash threshold. The validation images share the 37-image visual group with training; they are not a group-independent generalization set. The source provides no capture-session metadata, so perceptual grouping cannot prove session independence or rule out all related imagery.

Augmentation is applied only to training data. The selected test group is fixed before fitting this model; it is evaluated once after selecting the checkpoint and threshold on validation.

## Model and selection

TorchVision `FasterRCNN_MobileNet_V3_Large_320_FPN_Weights.COCO_V1` initializes the detector. The classifier/regression head is replaced for the three board-cell labels. The CPU run uses SGD, batch size 2, learning rate 0.003, seed 2026, one frozen-backbone warm-up epoch, then an unfrozen backbone; flips and brightness/contrast jitter are train-only. Ten epochs completed in 101.7 seconds. Epoch 10 was selected by validation mAP@0.50 = **0.9504**.

`boardwatch select-threshold` sweeps scores `[0.25, 0.35, 0.45, 0.55, 0.65, 0.75, 0.85, 0.90]` on validation only. It maximizes micro-F1 at IoU ≥ 0.50; ties prefer higher precision and then a higher score threshold. The selected threshold is **0.55** (validation precision 0.846, recall 0.951, F1 0.895; 77 TP, 14 FP, 4 FN). These validation results are used for model selection and are not independent of the training visual group.

The CLI, API, and browser demo default to the selected 0.55 threshold for this checkpoint. After retraining, use the new validation-selected value explicitly for evaluation and update `DEFAULT_SCORE_THRESHOLD` if the interactive default should follow the new model.

## Group-held-out test results

On the 20-image/180-box test group, at the validation-selected score threshold **0.55** and IoU ≥ 0.50:

- mAP@0.50: **0.7986**
- Micro-precision: **0.7024**
- Micro-recall: **0.8000**
- Micro-F1: **0.7481** (144 TP, 61 FP, 36 FN)
- Per-class AP@0.50: empty **0.8227**, white circle **0.8671**, black cross **0.7061**

The score is lower than the previous random image-level split, consistent with the risk that similar frames had inflated the original estimate. The current estimate is still based on one small test visual group, not an independent multi-session or external benchmark. The black-cross class has the lowest AP, and no broad-domain claim is made.

## Metrics

For each class, predictions are sorted by confidence and greedily matched to same-class ground-truth boxes in the same image. A match is a true positive when IoU is at least 0.50 and the ground-truth box has not already been matched. AP uses detections with score ≥ 0.001 and is the 101-point interpolated area under the precision-recall curve at IoU 0.50. `mAP@0.50` is the unweighted mean over classes present in the split; it is not COCO mAP@[.50:.95]. Precision, recall, and F1 use the validation-selected confidence threshold and the same IoU threshold.

## Generated evidence

- `reports/dataset_summary.json`: source revision, visual group sizes, class counts, and split sizes.
- `reports/split_manifest.csv`: image-level assignment, perceptual group, dimensions, and file hashes (no image pixels).
- `reports/similarity_audit.json`: hash method, threshold, component split counts, and test-isolation check.
- `reports/training_history.csv` and `reports/training_summary.json`: losses, validation metrics, and portable training configuration.
- `reports/threshold_selection.json`: validation-only confidence sweep and selected threshold.
- `reports/inference_latency.json`: CPU latency spot measurement.
- `reports/evaluation_test.json` and `reports/evaluation_test.png`: held-out test metrics and aggregate chart.
- Local-only `reports/example_test_overlay.jpg` is regenerated by evaluation but ignored by Git; it contains a source photo and is not part of the public repository.

The CPU latency report is a 77.3 ms median (67.8–83.9 ms) over eight timed 640×480 predictions after two warm-ups in this environment. This spot measurement is not a guaranteed device benchmark.
